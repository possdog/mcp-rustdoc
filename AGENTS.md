# mcp-rustdoc

This document provides high-signal context for AI agents working on this project.

## Architecture & Code Boundaries

*   **Entrypoint:** `src/main.rs` initializes the Tokio runtime and MCP stdio server.
*   **Server Implementation:** `src/server.rs` contains `RustdocServer` which implements `rmcp::ServerHandler`.
    *   **Crucial deviation from rmcp docs:** This project *manually* implements `list_tools` and `call_tool` rather than using `rmcp`'s `#[tool]` and `#[tool_router]` macros. This allows custom manipulation of the generated JSON schemas.
*   **Components:**
    *   `src/fetcher.rs`: Downloads and decompresses `.json.zst` from docs.rs.
    *   `src/local.rs`: Generates rustdoc JSON for local workspace crates via `cargo +nightly rustdoc`.
    *   `src/resolver.rs`: Resolves versions implicitly by checking `Cargo.lock` -> `Cargo.toml` -> docs.rs latest.
    *   `src/render.rs`: Converts `rustdoc-types::Crate` structs into LLM-optimized Markdown.
    *   `src/cache.rs`: Caches decompressed JSON to disk using the `dirs` crate (e.g., `~/.cache/mcp-rustdoc/`).

## Toolchain & Execution

*   **Run Server:** `cargo run --release` (runs on stdio).
*   **Logging:** All logs must go to `stderr` because `stdout` is used for MCP stdio protocol communication. Run with `RUST_LOG=debug cargo run` to see logs.
*   **Local Crate Requirements:** Generating documentation for local (unpublished) crates requires the **nightly** toolchain (`cargo +nightly rustdoc`).
*   **Format version:** The project targets a specific `rustdoc-types` format version (currently v0.57).

## Important Quirks & Conventions

*   **Custom Schema Generation:** In `src/server.rs`, `json_schema_for` implements a specific workaround to strip `"null"` types from `anyOf` arrays generated by `schemars`. This is required to maintain compatibility with strict schema requirements in Vertex AI / Gemini. Do NOT remove this workaround or switch to standard `schemars` generation without testing against strict clients.
*   **Immutable Cache:** Fetched docs.rs JSON is cached on disk permanently. Local workspace crates are re-generated on the fly or cached by Cargo.toml hash.
*   **No HTTP/SSE:** Transport is purely stdio. Do not attempt to add HTTP/SSE transport unless specifically requested.
*   **Markdown only:** All MCP tools return Markdown strings, never HTML or raw JSON trees. Render type signatures as Rust code blocks and keep outputs concise.
*   **Version Resolution is Internal:** The agent never needs to call a separate tool to resolve versions. It's baked into every tool that accepts `crate_name`.

## MCP Tools
There are 6 standard tools: `list_items`, `get_item`, `search`, `implementations`, `implementors`, and `list_workspace_crates`. All except `list_workspace_crates` accept `crate_name` and an optional `version`.
